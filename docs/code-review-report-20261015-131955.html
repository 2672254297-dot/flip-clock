🔴严重问题（需立即修复）

严重 flipclock_overlay.py:972-976（do_GET 静态文件分支）

任意本机文件读取：绝对路径可绕过根目录限制

静态文件分支用 rel = os.path.normpath(path.lstrip("/")) 后直接 os.path.join(ROOT, rel)，只用 rel.startswith("..") 挡住了相对穿越。当 rel 是盘符/绝对路径时，NT 路径语义下 join 会丢弃 ROOT，于是请求变成读取本机任意路径。
实测证据（本机 raw socket）：
GET //C:/Windows/win.ini → 200 OK，返回文件内容；
GET /C:\Windows\win.ini → 200 OK；而 GET /../flipclock_overlay.py → 404（说明只挡住了相对形式）。
响应同时带 Access-Control-Allow-Origin: *，因此用户访问的任意网页都能跨域读取其可读的任意文件（文档、配置、其它软件的凭据文件等）。
修复建议：用白名单或 Path.resolve() + relative_to() 强制目标必须落在允许目录内；更稳妥的是静态服务只放行明确允许的文件，其余一律 404。 
ALLOWED = {"index.html"}
def _serve(self, url_path):
    base = Path(ROOT).resolve()
    rel = unquote(url_path).lstrip("/")          # 先解码再做路径判断
    target = (base / rel).resolve()
    try:
        target.relative_to(base)                 # 绝对路径/盘符路径会在此抛错
    except ValueError:
        return self._text(403, "forbidden")
    if target.name not in ALLOWED and target.suffix != ".png":
        return self._text(404, "not found")
    return self._file(str(target))
严重 flipclock_overlay.py:910-913（_cors）、978-1050（do_POST 全部控制接口）

控制接口无鉴权 + 通配 CORS：任意网页可遥控屏保（CSRF）

_cors() 对所有响应发送 Access-Control-Allow-Origin: *，而 /__exit、/__config、/__theme、/__hold、/__ack、/__page 均不校验来源、不校验 token、不校验 Host。页面 URL 里虽带 ?t=<token>，但仅用于设置窗口标题，未参与任何鉴权。
实测证据：POST /__exit（带 Origin: http://evil.example）→ 200 OK；随后宿主日志出现「页面请求退出」并开始清理进程。
影响：恶意/被挂马的网页可以：关闭屏保（{"enabled": false}）、退出手动时钟（/__exit）、篡改配色与 theme.json、反复声明 hold 让屏保永不退出；DNS rebinding 还能绕过部分浏览器的同源限制。
修复建议：1) 校验 Origin/Referer/Host 只允许 127.0.0.1:<port> 与 localhost:<port>；2) 把启动 URL 里的 token 真正用起来：POST 必须带 X-FlipClock-Token 且与宿主一致；3) 去掉通配 CORS，改为精确来源。

中等 flipclock_overlay.py:766-777（maybe_release_browser）、876-898（kill_profile_browser）

监测线程里同步执行 PowerShell + taskkill，最长阻塞 30 秒

tick() 在按需启动模式会调用 maybe_release_browser()，后者同步执行 kill_profile_browser()：内部先跑一次 PowerShell（subprocess.run(..., timeout=30)）枚举进程，再对每个 PID 调 taskkill（每个 timeout=20）。这段时间整个监测循环停摆，表现为「动了鼠标要等几秒才退出屏保」，在进程多/杀进程慢时更明显。
修复建议：把清理工作丢到独立线程（清理期间先复位 hwnd/visible 状态，让主循环继续响应输入）；或改用 Win32 API 直接结束进程，避免起 PowerShell。 
def maybe_release_browser(self):
    if self.config.get("keepBrowser", True) or self.args.no_browser:
        return
    log("🧹 按需启动模式：结束时钟浏览器进程")
    self.proc, self.hwnd = None, None      # 主循环立刻继续
    threading.Thread(target=kill_profile_browser, kwargs={"quiet": True},

中等 flipclock_overlay.py:577-586（patch_theme）、381-390 / 456-462（save_config / save_theme）

theme.json 无取值/长度校验，且配置文件写入不是原子的

patch_theme() 只做 isinstance 类型检查：img 可以是任意长字符串（写入 theme.json 造成磁盘膨胀，页面也会把它拼进 CSS 值），mask 不校验范围。

中等 flipclock_overlay.py:336-349（force_hide_cursor）

隐藏光标的『压计数』只在第一次生效，之后无法纠正被抬高的计数

函数注释明确说「别的程序调用过 ShowCursor 会把计数抬上去，所以循环压到 <0」，但循环被 if not _cursor_hidden: 包住：一旦 _cursor_hidden 已为 True，后续调用只执行 SetCursor(None)，不再压计数。于是「我们隐藏 → 别的程序把计数抬起来 → 箭头重新出现」时不会再被纠正，与注释声称的设计意图不一致。
修复建议：把压计数改成幂等操作（每次想隐藏都压到 <0），并在每次进入隐藏态时调用。 
def force_hide_cursor():
    global _cursor_hidden
    for _ in range(64):                 # 幂等：每次都压，纠正被抬高的计数
        if user32.ShowCursor(False) < 0:
            break
    _cursor_hidden = True
    user32.SetCursor(None)
中等 flipclock_overlay.py:1065-1066（--idle-seconds）、508-514（threshold）

命令行阈值不做上下限校验，极小/负值会造成显示抖动

--idle-seconds 是 float 且无校验，threshold() 直接返回该值。传 --idle-seconds 0 或负数时，tick() 里 idle >= threshold 恒为真 → 立即显示，紧接着又因 idle < 0.7 触发隐藏，出现反复显示/隐藏的抖动与日志刷屏。
修复建议：在 threshold() 或参数解析处夹到合理区间（例如 ≥1 秒），与 patch_config 里已有的 10~86400 秒夹取保持一致。 
def threshold(self):
    secs = float(self.args.idle_seconds or self.config.get("idleSeconds") or 0)
    if secs > 0:
        return max(1.0, min(86400.0, secs))     # 与设置页夹取范围一致
    return float(self.config.get("idleMinutes") or 10) * 60.0

✅代码优点

状态机设计克制且考虑了失效场景：hold（页面保持显示）带 3 秒服务端超时、淡出用 transitionend + 500ms 兜底再回 ack、宿主等 ack 有上限——页面崩溃或卡死都不会把屏保钉在屏幕上，也不会「硬切」。
单实例与端口处理很细致：先查 PID 存活、再用 connect_ex 探测端口（正确规避了 Windows SO_REUSEADDR 导致 bind 探测恒成功的坑），端口被占自动顺延；进程清理按 --user-data-dir 精确匹配，不误杀用户自己的 Edge。
把「空闲时间」抽象成可注入来源（--idle-source），使端到端自测可以确定性复现，不受「测试者本人在用电脑」影响——这是一个很实用的可测试性设计。
自测覆盖真实链路而非 mock：真启动 kiosk 窗口、真截图做像素断言（顶部是否全黑、数字是否渲染）、真合成键鼠、真检查进程与端口清理，并对环境干扰（用户按住 Alt、高权限窗口丢弃合成输入）明确记为 SKIP 而不是误报失败。
注释与文档解释「为什么」而不只是「做什么」：SO_REUSEADDR 误判、ack 与淡出动画的竞态、预置 profile 抑制 Edge 首启同步弹窗、ShowCursor 计数会被其它程序抬高……后来人不需要重新踩一遍。
页面侧没有任何远程脚本、没有 eval，innerHTML 只用于自身的静态模板，数字与提示文本一律走 textContent，无用户内容注入面（XSS 面很小）。

def _guard(self):
